fix(chat): 专家执行轮消息顺序两态统一为因果序（思考→专家→聚合）

问题：实时流的聚合正文写进发送时预建的占位消息（id 还交给后端当
聚合落库 id），专家消息后到插在它后面——综述显示在专家上方；刷新后
按库序变成「专家→思考→聚合」——两态不一致且都不等于因果序。

修法（消息表行序=因果序，两态同源）：
- commander 规划落库时插入思考载体消息（content 恒空，排在专家
  之前；幂等按 run_id），plan.created 事件携带其 id，前端把占位
  消息原位改写成它（renameMessageId）——实时流与刷新回放同一条
- 聚合消息 id 与前端解耦：run 创建时生成 state.aggregate_message_id
  贯穿全图（aggregator 落库/流式转换层/事件三者同源，transform 按
  节点路由目标 id）；聚合 delta 按事件自身 id 在尾部创建消息
  （SSE 层向 onChunk 透传事件 + RAF 批处理层新增 retarget）
- 刷新回放的思考重建改挂该 run 的载体行（老会话回退挂最后一条
  助手消息）；LLM 上下文构建跳过空正文载体行
- resume 的 message_id 贯通链整体退役：ResumeRequest 字段、
  recovery/stream 两层传递、resume 占位预建、done 时的占位步骤
  迁移块（其服务的中断恢复场景已由载体行落库根治）

简单模式不受影响（direct_reply 仍挂请求侧 id）。
E2E 三层验证同一因果序：实时 DOM 序 / 刷新回放序 / DB 行序。
测试：后端 493 绿（run_thinking 契约 +1、七处旧契约随链路更新）、
前端 97 绿（plan.created 改写 +2）、tsc/build 绿。
